## Decisions and work contracts

### 1. Version-aware effective OpenCode configuration (AOR31-01)

Replace the unsafe shared precedence assumption around
`_opencode_config_files`, `_opencode_child_config`,
`opencode_provider_observation`, `routing_fingerprint`, `opencode_env` and
their Doctor/dispatch/migration callers. Keep existing worker profiles and gates.

- Prefer the supported executable's **normalized, non-inference** config output.
  V2.2.7: `debug config --standalone` returns ordered entries, not one merged
  object. V1.18.35: `debug config` returns a resolved object. Exit 0 is not proof
  that a field survived normalization. Implement dialect-specific validation
  and folding using actual upstream provider/model/variant overlay semantics.
  Do not apply generic recursive dictionary merge to all V2 arrays/settings.
- Establish one shared prepared child context: resolved executable/version and
  identity, project cwd, scrubbed environment, generated inline controls,
  effective routing observation and source identities. Preflight and actual
  dispatch must use the same routing-relevant bytes and environment. Recheck
  material source/expansion identities before launch; drift blocks, never
  silently re-pins or selects another route. Keep V2 private `--standalone`.
- Source discovery is version-aware. In V1.18.35 ordinary global files still
  load with `OPENCODE_CONFIG_DIR`; that directory is an additional late source.
  In V2.2.7 `OPENCODE_CONFIG_DIR` replaces the global config root. For both,
  explicit `OPENCODE_CONFIG` follows the applicable global layer. Correctly
  handle project ancestry/boundaries, `.opencode` directories, relevant HOME/XDG
  and project-disable flags, legacy `config.json` where supported, JSONC,
  inline and managed/platform settings. Account/remote/integration sources may
  contribute routing; observe authoritative entries or refuse unprovable cases.
  Do not fetch provider inference to discover them. Do not assume a current
  documentation page describes every supported binary.
- Normalize supported legacy V1 `provider`/`options` material under V2 too;
  native and legacy keys may coexist. Observe actual provider/model/selected
  variant, endpoint, package/canonical remaps, auth mode and auxiliary routing.
  Preserve benign legacy all-Go config. A custom route is never Go consent.
- Bind all influential routing sources to content identities, including ordered
  source presence/absence, raw file content digests, expansion dependencies,
  inline/generated bytes, relevant environment identities, normalized routing
  and executable identity. Include material that normalization/redaction drops
  if its effect cannot safely be ruled out. Never persist raw secrets or raw
  normalized config from real user environments; redact diagnostics and store
  hashes. A masked endpoint is not evidence of a default endpoint.
- Inspector execution must be bounded, cancellation/deadline-aware, contained
  and fully cleaned up; it must not attach to/start a persistent shared daemon,
  install dependencies or invoke inference/startup hooks capable of charging
  before authorization. Do not blindly execute arbitrary config plugins during
  billing inspection. If safe normalized inspection is unavailable, use only a
  source-backed, regression-proven bounded adapter; otherwise fail closed.
  Fakes must implement real output contracts, never become a production bypass.
- Grants must authorize the observed route identity, not just its provider/model
  label. An old grant cannot authorize a changed endpoint through explicit
  migration or fingerprint refresh. Bind new grants to the resolved material;
  old unbound grants/pins must fail closed when they cannot prove that binding.
  Never auto-grant, auto-repin, reset usage or refund an attempted reservation.
  Keep old schema-3 state readable, explain safe new-run/explicit migration
  handling, and retain schema-2 backup-first migration. Do not mutate live runs.

Required regressions: independent audit's three exact probes when available;
the saved reconstructed probes R2/R4/R5; V1 global retention/custom-directory
ordering; V2 global-root replacement and explicit override; project and managed
versus inline precedence; V1/V2 legacy/native coexistence, model/variant/remap
and auth/expansion identity; unreadable/malformed/masked/unresolved material;
material drift after inspection; default legacy Go; granted and ungranted
multi-provider/fallback paths; missing/failed inspector and process cleanup.
Assert rejected routes spawn no inference child, create no phantom active job,
and neither consume authorization nor count a model call before reservation.

### 2. Runtime input content in read-only integrity (AOR31-02)

Extend `source_write_projection` / `source_mutation` and shared consumers, using
the existing bounded runtime manifest instead of a second unrelated scanner.

- Include relevant ignored executable/config files as content identities in
  addition to HEAD/index/dirty/untracked source. Compare additions, deletion,
  target/content changes and renames; retain useful bounded path diagnostics.
- Include symlink text and relevant target content. Cover in-project links,
  target-only edits, retargeting, dangling/outside links and directory links.
  Traverse only with bounded cycle-safe rules or mark relevant unresolved
  links unprovable. Never silently certify an unreadable/truncated/incomplete
  projection. Project declarations cannot hide a write during the same stage.
- Exclude timestamps, environment/toolchain/config provenance and other volatile
  non-file metadata from *write detection*. Those keep their existing separate
  provenance checks. Byte-identical pre-existing dirty/ignored files remain
  valid. Do not revert user files on rejection.
- Apply this at success, invalid-report/nonzero/timeout, cached/recovered
  completion, acceptance and integration boundaries. Preserve existing stopped
  versus uncertain ownership logic. Old integrity bindings cannot silently
  certify a stronger check they did not record; invalidate safely, retain history.
- Keep the existing explicit limitation: boundary snapshots cannot detect
  transient writes restored to identical bytes; this adds no OS isolation.

Required regressions: fake planning mutates an ignored `.py` and is refused;
ignored config and symlink cases; review, acceptance/integration and recovery;
failure/malformed report; unchanged dirty/ignored inputs and volatile-metadata
changes do not falsely trigger source mutation. Preserve original source/
provenance/decision-binding regressions.

### 3. Bounded independent ledger lock (AOR31-03)

Use a dedicated grant-ledger lock helper for registration/reservation/release;
do not change supervisor-wide `exclusive()` to blocking.

- Add `limits.max_grant_lock_wait_seconds`, default **5.0**, with finite-positive
  validation and a backwards-compatible default for configs omitting it.
  Monotonic wait/retry must be capped by that limit and the remaining stage
  deadline. A short polling interval (at most 50 ms) is sufficient.
- Thread deadline/cancellation context through `call_model` → reservation and
  applicable ledger operations. Check authoritative parent run pause/cancel,
  including nested Explorer; never wait on an artifact directory's controls.
  Check expiry/cancellation before consuming after acquisition and recompute
  remaining child budget after inspection/wait, before any child starts.
- Keep read/check/reserve/atomic-write in the same critical section. Replay
  reservation IDs idempotently. A crash after durable reservation conservatively
  consumes it; retrying that ID must not consume again. Release only where
  launch is proven never attempted. No stale-state overwrite or oversubscription.
- Distinguish temporary lock-wait timeout, cancellation/stage expiry and actual
  missing/exhausted authorization in durable diagnostics. Contention is not
  “another supervisor owns this run.” No phantom active job on rejection.

Required **separate-process** regressions: sufficient capacity with genuine
overlap succeeds within the bound; contenders exceeding capacity never overrun;
holder releases; bounded timeout; cancel/pause/deadline while waiting; holder
crash releases kernel lock; crash before/after durable reservation; same-ID
replay and stale parent saves; supervisor ownership remains nonblocking.
Synchronize with pipes/events/files, not probabilistic scheduling assertions.
